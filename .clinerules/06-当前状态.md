# 当前状态（2026-08-05，fxTitle 恢复系统默认 + P/Invoke 最小权限经验）

## fxTitle 增强音频标识符恢复系统默认（2026-08-05 上午，未提交脚本）
- **问题**：之前手动测试把 `{b725f130-47ef-101a-a5f1-02608c9eebac},10`（fxTitle）改成 "VxAPO" 未恢复 → 播放器无法将设备当音频设备/格式消失/音量失效/增强音频标识符显示 vxapo
- **根因（ACL 实证 fxtitle_acl.txt）**：MMDevices 端点键 FxProperties Owner=SYSTEM，但 **DACL 无 SYSTEM ACE**（SYSTEM 想写也被拒——schtasks /ru SYSTEM 实证 "错误: 拒绝访问"）；BUILTIN\Administrators 仅 SetValue/ReadKey（无 CreateSubKey），Users 仅 QueryValues/SetValue/CreateLink，**TrustedInstaller 才有 FullControl**
- **为什么 .NET OpenSubKey(writable) 也被拒**：OpenSubKey 写模式请求的权限掩码（含 CreateSubKey 位）超出 DACL 授予范围 → 0x80070005
- **修复（P/Invoke 最小权限，fix_fxtitle_pinvoke.ps1）**：advapi32 `RegOpenKeyExW(HKLM, path, 0, KEY_QUERY_VALUE|KEY_SET_VALUE)` + `RegSetValueExW(REG_SZ)`——精确请求 DACL 已授权的权限位，OPEN_RC=0 / SET_RC=0，fxTitle 恢复 "Microsoft Audio Home Theater Effects"（2026-08-05 10:18 实证）
- **教训**：
  1. **勿手动改系统注册表值**（fxTitle 等增强标识符），测试完必须恢复原值
  2. 密钥级 DACL 可能无 SYSTEM ACE——「SYSTEM 最高权限」是误解，SYSTEM 只对**自己为 Owner 或有 ACE** 的键有隐式权；此处 Owner=SYSTEM 无 ACE = SYSTEM 也要「拒绝访问」的实例
  3. 写受限键用最小权限位（KEY_SET_VALUE|KEY_QUERY_VALUE）P/Invoke，别用 .NET OpenSubKey 写模式（掩码过大必拒）
  4. schtasks /tr 内嵌引号多层解析易坏（第一次失败）；独立脚本路径参数最稳
