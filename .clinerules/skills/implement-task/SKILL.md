# 实现路线清单任务

从 `roadmap.md` 中选取 **Spec-Finalized** 状态的任务，按规范完成实现。

> **仓库定位**：本仓库（vxapo-driver）只存放 `src/` 实现代码。
> `roadmap.md` / `changelog.md` / 主规范及子规范文档均在 **`../模块引用规范/`**（全局规范仓库）。
> 本 skill 中所有对规范文档的引用，默认基准路径为 `../模块引用规范/`。

## 前置条件

1. 确认任务状态为 **Spec-Finalized**（未定稿的任务不得进入实现——roadmap-rule 硬门禁）
2. 读取任务条目中的"影响模块"和"规范落点"，确定实现边界
3. 若有依赖，确认依赖任务均已 `Done`（一般已在规划时验证）

## 步骤

### Step 1：读 changelog

读取 `../模块引用规范/changelog.md`，找到该任务对应的规范变更记录：

- 了解本次变更的概述和范围
- 确认涉及的章节号（精确到 `文件名 + 节号`）

### Step 2：读规范

根据 changelog 中的章节号，读取 `../模块引用规范/` 下对应规范文档（主规范或子规范）：

- 主规范：约束、安全要求、模块边界、"引用约束总表"与"禁止依赖链检查"相关条目
- 子规范：具体实现细节
- 逐条对照"引用约束总表"与"禁止依赖链检查"，确认实现不越界

### Step 3：实现

- **只修改"影响模块"中声明的文件**（不越权改其他模块）
- 遵循规范中的约束（RT 安全、锁策略、内存管理、DllMain 限制等）
- **不得引入规范未声明的依赖或模块**（新依赖必须先走规范侧登记）
- 不修改规范文档（`../模块引用规范/` 下的任何 .md）

### Step 4：验证

- 编译通过（cargo check / build）
- 相关测试通过（cargo test）
- 自查是否有 RT 路径违规：分配（Box/Vec push/String）、I/O、锁间接（Mutex 内耗时操作）
- 对照该条目 DoD 中的"实现验收"逐条核验

### Step 5：报告（不直接改状态）

**执行端无权将条目置为 `Done`、无权回退状态**——Done 需规范侧合规核对后标记（roadmap-rule）。

实现完成后，在 roadmap.md 对应条目末尾追加**实现完成报告**：

```
### 实现完成报告
- DoD：☑ 实现 ☑ 测试
- 自查结果：{RT 无违规 / 引用约束无打破 / 未引入未声明依赖}
- 新增/修改文件：{实际触碰的文件，须 ⊆ 影响模块声明}
- 遗留问题：{无 或 描述}
```

通知规范端 Agent 进行合规核对，由规范侧决定是否标记 `Done`。
roadmap 中针对该条目的反馈只保留引用（`> 反馈记录：feedback.md #PX-X`），正文统一外置（v8.0）。

### Step 6：规范不可行时的反馈（v8.0：写入 feedback.md）

实现中发现规范不可行或有遗漏：

- **不得绕过规范自行实现**
- 不动状态字段 / 不修改规范文档正文 / 不写 roadmap 反馈正文
- 按 `.clinerules/feedback-rule.md` 向规范仓库根目录 **`feedback.md`** 追加记录（逆序插入）：

```
### [PX-X] <一句话问题标题>（<vX.Y> + 执行端反馈）
**影响版本**：规范 vX.Y
**问题**：{触发场景 / 现象 / 根因}
**规范侧判定**：（留空，规范侧核对后填）
**修订记录**：（规范侧修订后追加）
**状态**：待修订
```

**执行端只写「问题」+「影响版本」**；规范侧核对后填「规范侧判定」、修订后填「修订记录」+「状态」。
roadmap 对应条目追加一行引用：`> 反馈记录：feedback.md #PX-X`。

待规范端修订并重新定稿后执行端补实现回归；本任务保持 `Spec-Finalized`（不进入完成）。

## 权限边界

| 动作 | 执行端 | 规范侧 |
|------|--------|--------|
| 实现 + 测试 | ✅ | — |
| 追加"实现完成报告" | ✅ | — |
| 追加"反馈"（状态回退建议） | ✅（仅建议） | — |
| 标记 `Done` + 归档至"已完成"区 | ❌ | ✅（合规核对后） |
| 状态回退 `Spec-Drafting` | ❌ | ✅ |
| 修改任何规范文档（`../模块引用规范/`） | ❌ | ✅ |

## 反例（禁止）

- 把 `Backlog` / `Spec-Drafting` 状态的任务直接实现（跳过硬门禁）
- 自行将条目置 `Done`（绕过规范侧合规核对）
- 修改影响模块之外的文件，或引入规范未声明的依赖
- 直接修改规范文档 / 版本号 / changelog
- 实现中发现规范不足时"绕过去"继续编代码
