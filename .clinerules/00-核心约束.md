## XML 标签格式铁律（2026-08-04 追加，杜绝反复 DSML）
工具调用是 XML 格式，**标签拼写错误会导致参数丢失或解析失败**。历史教训：
- 曾反复把 path 参数闭合标签打成键盘位移的错字（数字/错字符后缀），参数被吞报「Missing value」；
- 曾把 diff 参数写成「空参数」——根因是 diff 内容里直写了尖括号包裹的标签字形（如 path 闭合标记、diff 闭合标记），
  破坏了工具调用自身的 XML 结构（解析器把内容里的闭合标记当成真实标签结束，后续全部丢失）。

每次工具调用前逐字符核对：

1. **闭合标签必须与开标签精确同名**：path 参数用与开标签对称的 p-a-t-h 字符闭合；禁止尾随数字/错字符。
2. **内容中禁止出现尖括号标签字形**：凡是要说明「某标签长什么样」，一律用文字描述
   （如「path 闭合标记」「diff 标记」）——绝不原样写出「左尖括号 + 斜杠 + 标签名 + 右尖括号」组合，
   那会让解析器认为标签已结束，后续内容全部丢失。
3. **diff 三件套必须完整**：SEARCH 标记、分隔标记、REPLACE 标记三者齐备且顺序正确；
   SEARCH 内容与文件逐字符一致（含缩进/空行）。
4. **失败即标签错**：工具报「Missing value」或「parameter was empty」时，先检查
   标签拼写和内容是否含尖括号标签字形——**不是内容太长**，不要换方案折腾。
5. **发送前自检**：标签成对、内容无尖括号标签字形、diff 三件套完整；怀疑即重写整个调用。

必须主动更新规则文件，不要等用户提醒：

### 必须更新
- `06-当前状态.md`：commit hash、已完成/待做清单、未解疑问

  - 每次遇到未解决的技术问题，追加到"未解疑问清单"
  - 问题解决后从清单中移除

### 条件更新（发生变化时才更新）
- `02-项目结构.md`：增删文件时维护目标树
- `03-架构决策.md`：用户确认了新的架构决策时，追加或修改对应条目
- `05-dsp-factory.md`：新增工厂、注册顺序变更、构造器签名变化时更新表格
- `04-开发环境.md`：踩到新的环境陷阱时追加记录

### 禁止修改
- `00-核心约束.md`（本文件）：没有用户明确指示不得自行修改
- `01-windows-rs-api.md`：API 签名经实测确认后不得臆改，如发现新 API 需要追加，必须先通过可信渠道验证

### 更新方式
